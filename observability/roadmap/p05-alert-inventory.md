[P04 inventory](p04-metrics-inventory.md) and its captured
[machine inventory](p04-validation/evidence/metrics-inventory.json), not a deployed scrape.

## Implemented rule inventory

[Rules](../p05-candidate/prometheus/rules/p05.rules.yml) contain **15 recording rules and
33 alerts in 7 groups**. [Alert manifest](p05-validation/evidence/alert-manifest.json)
records every name, expression dependency, evidence, severity, threshold rationale and pending duration.
Expressions themselves are authoritative; the test suite checks all raw selector names against P04
inventory or the three explicit Prometheus scrape-generated contracts.

| Category | Alert families | Count |
|---|---|---:|
| Availability | Service scrape unavailable; expected User/Learning/Prometheus target absent | 4 |
| Integrity | Stale samples; slow scrapes; missing User/Learning core metrics; missing latency bucket | 5 |
| HTTP | Warning/critical 5xx; warning/critical slow fraction; absolute failure burst | 5 |
| Security | Authentication failure spike; authorization denial spike | 2 |
| Dependencies | Warning/critical JWKS observed failures; slow JWKS responses; unresolved attempts; SQL connect and Learning DB failures | 6 |
| Capacity | Allocated SQL pool busy; reactive pool warning/critical; User memory and Learning heap warning/critical; two CPU warnings; scrape sample warning/critical | 11 |

All application alert contracts depend on unaccepted P04 runtime instrumentation. P05 does not
upgrade their evidence. HTTP ratios require >=1 request/second; the separate >=50 failures/5m
burst covers material lower-volume failures. Idle optional families are not declared missing.
Latency uses the captured 2/2.0-second bucket and excludes the import route; it is a tail fraction,
not an averaged percentile. Raw framework names remain unchanged.

## Deferred alerts

Do not create hypothetical series to fill gaps. Deferred: shared JWKS server availability;
Fluent Bit drops/retries/backlog/oldest age; OpenSearch ingest/index/cluster; Nginx upstream/status;
host/volume free bytes and exhaustion forecasts; server DB waits/max pools; TSDB head/WAL and
rule-evaluation self metrics; Grafana errors; external deadman and notification delivery;
low-traffic readiness/dependency canaries. Each needs scoped exporter/access evidence and
bounded labels before adoption. Prometheus cannot detect its own complete outage or a stopped
rule evaluator; a self-`up` rule is not an independent watchdog.
