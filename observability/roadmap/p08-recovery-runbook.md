# P08 backup and isolated recovery runbook

Local development is approved under the [development policy/exception register](p08-development-policy.md). Current accepted procedures follow. The older general/off-host candidate procedure below remains reference for separately approved production work. Never use protected stores for destructive validation.

## Current approved development operations

Configuration: `D:\japanese-learning\.local\p08-development\config.json`; key: its sibling `backup.key`, protected by current-user/SYSTEM ACLs. Both are ignored. Destination: `D:\JapaneseLearningBackups`; it is outside this Git repository and is not off-host. Never regenerate/replace the existing key. Losing D: can lose both key and backups.

Setup/review: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File observability/p08/Configure-P08Development.ps1 -InstallSchedule`. This uses a process-only script-policy exception; it does not change machine policy. Setup preserves existing key/config and refuses conflicting task actions. Review any future policy/config change explicitly. Paths are absolute in the private config; destination and daily time are setup parameters.

Manual acquisition: `node observability/p08/local-backup.cjs .local/p08-development/config.json --force`. Normal invocation without `--force` can return NOT_DUE. The installed daily task always forces fresh acquisition; it exports actual telemetry, verifies the encrypted generation and performs guarded seven-day cleanup. Do not invoke the older immutable-input candidate runner expecting it to acquire actual stores. Query warnings, incomplete searches, budget exhaustion or integrity/authorization failures return nonzero, never a partial success. Review task history, private `.local/p08-development/logs/` and uniquely named JSON evidence. Do not delete unknown destination files to make a job pass.

Manual complete drill: `node observability/p08/local-drill.cjs .local/p08-development/config.json`. It selects the newest authenticated actual local generation, rejects invalid data before creating a plaintext restore directory, generates fresh isolated identities, restores/verifies native stores, ingestion and alert delivery/resolve, measures approved RPO/RTO, checks preservation, and stops only exact manifest-owned containers. It uses no live volumes, databases, notification destinations or application signing keys. Existing source credentials are never copied into targets. Disposable validation TTL is temporarily longer than source TTL solely to prevent archive expiry during comparisons; all target data remains bounded and is discarded on shutdown.

Installed tasks: `JapaneseLearning-P08-Daily` (03:00 local daily) and `JapaneseLearning-P08-MonthlyRecovery` (first day 04:00 monthly). Both are hidden, use the logged-in development account, have StartWhenAvailable enabled, and require Docker Desktop. They run while the desktop is locked but are not an always-on logged-off backup service. Both were executed through Task Scheduler and returned 0. Use `Get-ScheduledTaskInfo` to inspect next run and result; a running task result 267009 is not a successful completion. The common exclusive lock rejects overlap; review stale locks after an interrupted process instead of automatically deleting them.

Data boundaries: only canonical allowlisted application-log fields, original metric samples (no query resampling), traces, actual dashboard definitions, collector offset SQLite DBs and committed telemetry config are backed up. No raw producer-log/chunk copy, global OpenSearch security index, service secrets, Grafana credential-bearing DB, JWT keys or SQL Server/MySQL business content is included. Collector offset snapshots are archival recovery metadata; do not attach them blindly to live files/inodes or claim zero-loss replay. Recovery constructs new scoped identities. There is no in-place promotion/cutover operation.

Retention deletion is limited to `p08-local-<32 hex>.enc` with authenticated matching ownership; newest valid generation always survives. Legacy P08 names and unrelated files remain untouched. Bad keys, corrupt generations or links fail closed. Temporary plaintext exports and test credentials reside under the protected staging root, and only closed evidence-owned run directories are cleaned. Earlier fixture/evidence artifacts outside this development staging root remain intact. Completed target containers/networks are retained for inspection; do not restart them after their temporary bind sources have been cleaned. Rerun from the encrypted generation instead. Never use `down -v`, prune or restore over source data.

The policy's 1 GiB destination safety ceiling and 64 MiB input-package ceiling are explicit fail-closed limits. Original metric samples are split into eight six-hour gzip chunks to avoid native query sample limits and excessive package size. Unsupported native histograms or export warnings fail instead of omitting data. Source growth beyond these bounds needs reviewed capacity changes; production scalability is not claimed.

Rollback: disable only the two new scheduled tasks; restore the prior P08 code/config version using recorded hashes. Keep valid generations and the existing AES key. Do not undo Logs UI's LF line-ending correction, downgrade telemetry security, remove original volumes or revert application/authentication behavior.

## Backup invocation after approval

1. Copy `observability/p08/policy.example.json` into an approved ignored configuration location. Complete all policy fields using recorded owner decisions; a boolean does not itself constitute approval. Resolve destination/key/export paths as absolute paths. Ensure the off-host storage is independently recoverable without this laptop and uses authenticated encrypted transport. Grant the job create/read access only to its backup prefix. No delete privilege is required by these tools.
2. Provision a unique random 32-byte AES key through the approved custody process, outside Git and separate from the destination. Protect configuration, key files and staging with OS ACLs. Node `mode` flags alone do not establish Windows ACLs. Plan key recovery on the independent host, rotation and old-generation key availability. Tools do not generate or change any JWT key.
3. Prepare reviewed immutable native exports using separately scoped store identities and supported interfaces. OpenSearch: successful native application-index snapshots, no global/security state, dedicated approved repository and no concurrent repository mutation while staging its complete file set. Prometheus: supported consistent TSDB snapshot, never `cp` of live TSDB/WAL. Grafana/Fluent Bit: SQLite backup API with the appropriate data/offset/log boundary, never uncoordinated DB/WAL/SHM copies. Tempo: approved immutable block/checkpoint process; unflushed WAL loss must be measured. No current script performs these acquisitions against live services.
4. Set `package.artifacts` to objects such as `{ "id": "logs", "type": "opensearch-snapshot", "root": "ABSOLUTE_IMMUTABLE_EXPORT", "consistency": "immutable-native-export", "classification": "reviewed-telemetry" }`. Record external native validation/consistency provenance. A label is not a validation result. Set `newestRecoverableUtc` to the oldest latest-recoverable point across included data classes, never job start time. Replace it on every refreshed export. Select only reviewed configuration paths from the source allowlist.
5. Run `node observability/p08/backup.cjs run ABSOLUTE_CONFIG`. Exit 1 means the run failed; exit 0 can mean CREATED or NOT_DUE, not recoverability PASS. Capture its status/digest in the approved local monitoring integration without publishing payload or keys. Verify it from the destination with `node observability/p08/backup.cjs verify ENCRYPTED_PACKAGE KEYFILE` and conduct the native drill below. Read-only verification does not prove current destination authorization or off-host independence.
6. Once approved, configure the existing OS scheduler to invoke `powershell.exe -NoProfile -File D:\japanese-learning\observability\p08\Invoke-P08Backup.ps1 -Config ABSOLUTE_CONFIG` using its scoped account at the approved cadence. Run on a single writer; the exclusive lock rejects overlap. A stale lock requires operator review, not automatic deletion. The acquisition workflow must finish and publish a fresh immutable export before each invocation. No task or acquisition job is installed by P08 candidate tests.
7. Monitor missed runs, package budget, generation integrity and approved RPO. Retention expiration is reported as deletion candidates only. Preserve valid generations; owners must separately approve actual expiry/deletion and off-host budget enforcement. Key rotations need explicit generation-to-key custody records; the candidate single-key runner cannot inventory mixed-key generations in one destination.

## Independent restore

1. Declare the incident and record UTC start, data classes and expected recovery points. On the independent host, acquire the encrypted generation and authorized recovery key through approved transport/custody. Verify access is denied to unauthorized principals. Do not copy protected credentials from the original host.
2. Verify the package, then run `node observability/p08/backup.cjs restore ENCRYPTED_PACKAGE KEYFILE NEW_DIRECTORY`. The directory must not exist. Do not target a volume, live store path or existing backup repository. Authentication/integrity failure must leave no plaintext directory; a filesystem error during writing may leave an incomplete directory that must never be promoted.
3. Build a reviewed isolated manifest: unique owner/run/project, fixed candidate image digests, new data volumes, private network, no live endpoints/mounts or shared keys, budget/headroom and expiry. Reject collisions and missing isolation evidence. Reconstruct only approved test/store identities and certificates; never disable native security or certificate verification to make restore pass.
4. Register the decrypted OpenSearch repository **read-only** on the new target; restore named application indices with `include_global_state:false`. Require successful native shards, index health, mappings/settings and exact document IDs/count/digest plus representative queries. Native engine restore verifies data structures in addition to manifest hashes. For exported SQLite run `python observability/p08/native-sqlite.py OFFLINE_EXPORT` before service startup. TSDB/block/WAL integrity requires each store's supported checks and real query verification; package verification is insufficient.
5. Verify ingestion using synthetic markers, authenticated readers/writers and denied anonymous/invalid/incorrect-role requests. Rebuild and check Grafana/datasource queries, metrics/trace queries, collector offset/loss behavior and evaluated/delivered/resolved alerts to an approved isolated sink. Do not send an external notification without separate authorization.
6. Compute RPO = declaration minus latest recoverable event/config (per class). Compute full RTO = declaration through verified auth/ingest/query/dashboard/alert restoration, including retrieval/decryption, startup and dependencies. Compare only with approved targets. Local fixture elapsed times exclude off-host transfer and full-stack recovery and cannot satisfy R13.
7. Record images, versions, inputs/checksums, failed attempts, timings, approvals, privacy screening and protected before/after inventory. Stop only exact manifest-owned resources after checking ownership. Retain all volumes, snapshots and telemetry; no broad cleanup commands. Re-run from a new restore directory/resources for reproducibility.

## Business database integration boundaries (documentation only)

SQL Server's database owner owns database-native full/differential/transaction-log backup policy, recovery model and log-chain continuity, encryption/key custody, application-consistent restore, point-in-time recovery and isolated restore validation. A future integration may consume only approved backup identifiers, timestamps, success/native verification status and owner-approved RPO/RTO metadata. `RESTORE VERIFYONLY` alone is not business recovery acceptance. Do not read/copy `sqlserver_data`, issue BACKUP/RESTORE, run migrations or expose connection credentials from these telemetry tools.

MySQL's database owner owns supported consistent logical/physical backup choice, transaction/binlog/GTID boundaries, encryption/custody, schema/version compatibility and isolated point-in-time restore validation. A future integration consumes only approved job status, backup/recovery-point identifiers and timing metadata. Do not copy `mysql_data`, execute dumps, change binlogs, acquire business content or install backup jobs here.

Business DB schedules/RPO/RTO remain separately approved. P08 neither coordinates cross-database transactions nor promises recovery of application data. JWKS endpoint/token contracts remain unchanged; reference only committed observability metadata and externally reprovisioned service identities, never JWT public/private key bodies or Spring Boot resources.
