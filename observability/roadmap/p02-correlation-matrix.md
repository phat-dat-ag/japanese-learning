X-Correlation-ID is an opaque request diagnostic, never authentication identity. X-Caller-Service is bounded claimed metadata, never trusted identity. Quarkus X-Trace-Id may be a legacy response alias; legacy_trace_id remains separate. .NET's pre-existing random X-Distributed-Trace-Id fallback remains a response diagnostic for compatibility but is no longer a canonical recorded trace. W3C traceparent and valid active SDK trace/span IDs retain their own semantics; P02 neither creates spans nor introduces a tracer/exporter. No log adapter manufactures parent relationships.

No second Angular interceptor or browser telemetry SDK was introduced. Cross-origin requests preserve existing behavior; this phase does not authorize new allowed origins or correlation headers on external services. Database operations inherit request/business logging context where already supported; no new DB client hooks or DB spans were added. A fully observed browser/proxy/API/JWKS chain remains NOT VERIFIED until a separately authorized disposable run; actual request-triggered OIDC refresh propagation remains unverified and blocks a claim of complete runtime HTTP-hop correlation.
